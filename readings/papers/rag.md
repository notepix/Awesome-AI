# RAG：把检索文档作为生成模型中的隐变量

> Patrick Lewis 等，*Retrieval-Augmented Generation for Knowledge-Intensive NLP Tasks*，NeurIPS 2020；核对 [arXiv v4 全文](https://arxiv.org/pdf/2005.11401v4)。先修：[DPR](dpr.md)、[T5](t5.md)、[O06 RAG](../../docs/04-systems-agents-robotics/o-llm-posttraining-rag-agents.md#o06)。

## 原始 RAG 与常见工程管线

今天“检索后把文本塞进提示词”常被泛称 RAG。原论文更具体：用检索器给文档概率，用生成器给条件文本概率，再对潜在文档做边际化并训练。理解这个概率模型，有助于区分论文贡献与后来的工程习惯。

检索记为 $p_\eta(z|x)$，生成记为 $p_\theta(y|x,z)$。非参数知识库存放文档，参数模型负责组织输出。可更换知识库不等于自动可信：检索遗漏、证据冲突、生成幻觉仍分别存在。

## 两种边际化的区别

RAG-Sequence 假设整条输出由同一隐文档条件化：

$$p(y|x)\approx\sum_{z\in topK}p_\eta(z|x)\prod_t p_\theta(y_t|x,z,y_{<t}).$$

RAG-Token 在每个位置分别边际化：

$$p(y|x)\approx\prod_t\sum_{z\in topK}p_\eta(z|x)p_\theta(y_t|x,z,y_{<t}).$$

“和的乘积”与“乘积的和”一般不相同。实现可以把一个 batch 的 K 个文档展开为 $B\times K$ 个生成器输入，得到各文档各位置的词表 logits，再在对数域用 log-sum-exp 聚合。为每个 token 计算概率时，所有文档都条件化于同一个已生成前缀。

## 两份证据、两个 token 的完整例子

教学设检索概率 $p(z_1|x)=0.6,p(z_2|x)=0.4$。对于答案两个 token，在相同正确前缀条件下，文档1给出概率0.8、0.2，文档2给出0.3、0.9。

Sequence 概率为 $0.6\times0.8\times0.2+0.4\times0.3\times0.9=0.204$。Token 概率为 $(0.6\times0.8+0.4\times0.3)(0.6\times0.2+0.4\times0.9)=0.6\times0.48=0.288$。差异来自 Token 模型允许两个位置分别更多依赖不同文档。

答案只有一个 token 时，两式都成为 $0.6p_1+0.4p_2$，因此相等。这个例子也提醒：Token 模型可融合不同来源信息，但若两个来源相互矛盾，融合并不自动形成逻辑一致答案。

训练时最小化 $-\log p(y|x)$，不是简单把最高分文档的生成损失拿来训练。对检索概率求梯度会提高更能解释目标答案的文档权重，但 topK 候选选择与 ANN 搜索本身不是普通全可微算子。

## 训练与推理的实际约束

原文采用 DPR 式检索器与 seq2seq 生成器，训练时保持文档编码与索引固定，更新查询侧等参数以避免每步重建巨大索引。阅读 §2.4 时应注意具体可训练部分，不能把系统称作“所有模块全端到端更新”。

推理需要先检索，再按照所选变体处理生成概率。Sequence 解码牵涉不同文档条件下的候选与评分，Token 聚合则发生在每个位置。普通拼接所有文档的一次生成与这些边际化公式不是同一个模型，尽管都属于广义检索增强。

失败条件包括索引时效不足、chunk 缺上下文、检索分数未校准、生成器忽视证据、恶意文档含指令，以及以答案字符串重合替代事实支持判断。检索文本应视为待解释的数据，而非高优先级控制指令。

## 文档边际化如何给检索器分配信用

对整条答案而言，每篇候选文档都有两部分贡献：被检索到的先验权重，以及在该文档条件下生成目标答案的概率。把二者相乘并归一化，可以得到“已看到正确答案之后，各文档解释它的相对权重”。这类似隐变量模型中的后验责任。训练不是简单奖励检索分数最高者，而是鼓励更能支持目标输出的候选。

然而，如果生成器凭参数记忆就能回答，它可能在所有候选文档下都给目标较高概率，检索器收到的区分信号便弱。反过来，一篇无关文档偶然包含答案字符串，也可能在训练中得到信用。因此概率目标本身不等于证据真实性目标，必要时应结合独立的支持性标注或人工审核，而不是只看生成损失。

候选截断是另一个重要近似。真正支持答案的文档若根本不在前若干候选中，当前边际化只会在错误集合里分配概率。增大候选数量可能改善覆盖，也会增加计算与干扰；它不是免费提高质量的开关。比较时应记录候选数与输入长度，并分别测召回和生成，才能判断收益发生在哪个阶段。

多文档信息也可能冲突。一篇资料较旧、一篇较新，或者同名实体对应不同对象，逐词融合可能形成两者都未支持的混合回答。工程上应保留来源时间、实体和文档标识，要求答案中的关键断言能回到具体证据片段。这里的来源管理是对模型的补充，不应把原概率边际化说成已经解决事实溯源。

一个精简的教学诊断集可以包括四类问题：答案在首条证据中、答案只在后续证据中、候选证据相互矛盾、库中根本没有答案。分别检查模型能否使用后续证据、识别冲突和适当表达证据不足。若只挑选库中已有明确答案的问题，管线可能显得可靠，却没有暴露实际使用最常见的失败边界。

这一阅读方法也有助于比较原论文与现代检索拼接系统。前者有明确文档概率和边际化训练，后者可能依赖提示指令与上下文窗口。两者都可以评估同样的证据任务，但必须说明训练方式和输入预算，不能仅因都叫检索增强就视为同一种算法。

## 自测与答案

1. **两种 RAG 何时必然相同？** 仅有一个输出 token 时两式相同；一般多 token 情况不相同。
2. **检索分数最高的文档必然最有利于生成吗？** 不必，检索相关性与答案解释能力可能不一致。
3. **更换知识库能完全修正模型错误知识吗？** 不能，生成器可能忽略证据，且检索器可能找不到新内容。
