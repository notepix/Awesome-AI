# ReAct：把行动后的观察纳入下一步决策

> Shunyu Yao 等，*ReAct: Synergizing Reasoning and Acting in Language Models*，ICLR 2023；核对 [arXiv v3 全文](https://arxiv.org/pdf/2210.03629v3)。先修：[B12 规划与执行](../../docs/01-foundations/b-plus-classical-ai.md#b12)、[O07 工具协议](../../docs/04-systems-agents-robotics/o-llm-posttraining-rag-agents.md#o07)、[RAG](rag.md)。

## 核心是反馈回路

只在文本内部推演，可能沿着错误假设继续扩展；只调用动作，可能缺少对任务进展的解释与计划。ReAct 用交替的任务推理、动作和外部观察组织轨迹，让后续决策能根据环境反馈调整。真正产生新事实的是检索或环境返回的观察，不是模型给自己的解释。

论文的 Thought/Action/Observation 是可见轨迹格式与研究方法，并非可直接读取模型内部真实计算。教学和产品中可记录简短决策摘要、工具参数与结果，无需把冗长自由文本推理当作可靠执行证明。

## 状态、动作与终止

令历史 $h_t=(x,a_1,o_1,\ldots,a_{t-1},o_{t-1})$，策略据历史选择下一动作 $a_t$；环境返回 $o_t$。动作可为检索、定位文本、导航或最终回答，合法集合由任务环境规定。语言模型输出动作字符串后，还需要解析、参数检查、执行与结果回填。

若把行动看作条件序列生成，训练或提示都在建立 $p_\theta(a_t|h_t)$ 的行为模式。与固定 RAG 相比，关键变化是检索可由前一步观察触发，次数和查询也可调整。循环必须有终止规则、预算和无进展检测，否则“继续思考”可能变成反复调用同一工具。

## 一条完整、可检查的教学轨迹

任务：“馆藏说明中，甲馆和乙馆的开放年份相差多久？”假设工具只访问两条教学资料：甲馆“1988年开放”，乙馆“2003年开放”。

1. 决策摘要：需要取得两馆年份。动作 `search("甲馆 开放年份")`；观察返回资料A及1988。
2. 决策摘要：还缺乙馆。动作 `search("乙馆 开放年份")`；观察返回资料B及2003。
3. 动作 `calculate("2003-1988")`；观察为15。
4. 终止回答：“相差15年”，附资料A、B的来源标识。

这不是原论文实测轨迹，而是把状态变化讲清楚的小例子。若第二步返回“乙馆2003年改建，初建于1970年”，代理应识别“开放年份”证据不足，再查询，而不能为了完成任务直接取第一个年份。计算工具返回15只证明算术正确，不证明选取年份正确。

把轨迹转换成状态表，可记录 `year_a=1988`、`year_b=unknown`、`evidence=[A]`。结构化字段比仅依靠长文本历史更便于检查；这是工程实践联系，不应反称为原 ReAct 论文要求的唯一架构。

## 训练、提示与执行分离

原论文既研究少样本提示，也研究由轨迹数据微调的情况。提示中的演示示范如何使用工具；实际执行时必须等待真实观察。模型自己写出“Observation: 找到了答案”不能替代工具调用结果。

推理成本包括模型生成、工具延迟和重复检索。成功率之外还应看动作数、无效调用率和失败类型。对会产生外部效果的工具，授权与幂等处理属于执行层责任，不能指望语言格式自动保证。

失败边界包括工具结果被误当指令、未验证参数、同一失败动作无限重试、超出预算以及最终回答没有保留证据。日志中的“执行成功”必须来自工具返回，不应来自模型自述。

## 从可执行状态机看待工具循环

把工具调用封装成动作后，还需要定义哪些状态允许执行哪些动作。例如缺少实体名称时应先定位实体，已经得到答案时应终止，工具超时时应进入失败或重试分支。语言模型可以提出下一动作，但合法性检查和预算约束应有清晰规则。否则模型可能生成形式正确却与当前状态矛盾的请求。

观察的可信度也不是二元的。工具正常返回只表示调用完成，返回内容可能过时、不完整或来自不可靠网页。状态中可以同时保存原始观察和提取出的事实，并为事实保留来源。若事实提取发生错误，仍能回看原始结果，而不至于只剩模型改写过的摘要。这个设计尤其适合需要多次检索交叉验证的问题。

动作失败需要分类。参数格式错误通常可以修正后重试；服务暂时不可用可以有限重试；目标不存在或权限不足则不应无限循环。把所有失败都反馈为模糊的“出错了”，模型很难选择合理下一步。清楚的错误类型、剩余次数与已尝试内容，能让工具流程比单纯长提示更可控。

状态持久化解决的是中断后从哪里继续，但不自动保证外部动作只执行一次。若调用完成后、保存状态前程序中断，恢复时可能重复执行。这说明具有外部效果的工具需要幂等标识或确认机制。只读检索的重复通常代价较小，发送消息或修改记录的重复则会产生不同影响，必须按动作性质设计恢复策略。

评价工具型系统还应区分最终成功与过程质量。两条轨迹都答对，一条只调用两次工具，另一条反复搜索十次，可靠性与成本并不相同。可以记录无效动作比例、证据使用率、预算耗尽率和恢复成功率，使改进有明确方向。不要只以轨迹文字看起来连贯作为过程正确的证据。

在本地练习中，先给代理一个完全可控的小资料库和确定性计算工具，再故意注入缺失结果、错误参数和矛盾文档，观察状态如何改变。这样的失败注入能够检验反馈循环是否真实工作，也能区分模型决策错误与工具执行错误。它比只展示一次成功演示更能说明系统是否具备可诊断性。

## 自测与答案

1. **谁产生 Observation？** 环境或工具产生，不能由模型虚构后当证据。
2. **ReAct 一定比一次检索更好吗？** 不一定，简单问题可能只增加延迟与错误机会，应按任务评估。
3. **算术工具正确为何答案仍可能错？** 输入给工具的年份或实体可能选错，局部计算正确不代表证据链正确。
