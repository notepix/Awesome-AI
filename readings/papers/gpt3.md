# GPT-3：把提示中的示例与参数学习区分开

> Tom B. Brown 等，*Language Models are Few-Shot Learners*，NeurIPS 2020；核对 [arXiv v1 全文](https://arxiv.org/pdf/2005.14165v1)。先修：[F08 自回归目标](../../docs/02-perception-language/f-nlp-transformers-llms.md#f08)、[F10 数据与规模](../../docs/02-perception-language/f-nlp-transformers-llms.md#f10)、[F13 评估](../../docs/02-perception-language/f-nlp-transformers-llms.md#f13)。

## 论文提出的评测问题

能否只给自然语言任务说明和少量示例，就让一个大语言模型完成新任务，而不为该任务更新参数？GPT-3 将零样本、单样本和少样本提示放到同一规模研究中。它的重要性不只在参数量，更在评测接口：任务通过文本上下文指定。

这里 few-shot 指推理提示中的示例数量，不是拿几个例子训练若干梯度步。预训练当然进行了大量参数学习；“无需微调”不能误读为模型从未接受训练，或未见过类似任务。原文图 1.1 明确比较这些设置，§4 讨论基准污染，二者必须一起读。

## 概率形式与计算形状

自回归训练最小化

$$L=-\sum_{t=1}^{T}\log p_\theta(x_t\mid x_{<t}).$$

模型输出 logits 形状为 $B\times T\times |V|$。设任务说明为 $I$，示例为 $(x_1,y_1),\ldots,(x_k,y_k)$，待答输入为 $x$，推理是在固定参数 $\theta$ 下计算

$$p_\theta(y\mid I,x_1,y_1,\ldots,x_k,y_k,x).$$

序列答案概率是逐 token 条件概率的乘积，实际实现累加对数概率防止下溢。用候选答案评分时，要记录是否做长度归一化以及是否把题干部分计入分数；不同选择可能改变排序。

## 一次完整的上下文学习例子

教学任务为英中词对映射，提示是 `cat -> 猫\ndog -> 狗\nbird ->`。假设下一 token 的候选概率为“鸟”0.6、“鱼”0.3、其他0.1，贪心解码输出“鸟”。此过程只做前向计算；删除 `dog -> 狗` 会改变输入和注意力上下文，却没有修改模型参数。

再假设两个候选答案分词分别为 A：两个 token，概率 $0.8,0.7$；B：一个 token，概率 $0.5$。A 的序列概率 $0.56$，大于 B 的 0.5；其对数概率为 $\ln0.8+\ln0.7\approx-0.580$，B 为 $-0.693$。若另一个两词答案每词概率 0.7，总概率只有0.49，长度惩罚已能影响排名。评估协议必须先于观察结果确定。

提示中的例子还规定标签名称、输出格式与任务分布。把标签“正面/负面”改成“A/B”，需要示例建立映射；模型答错可能源于映射不清，而非完全缺乏情感识别能力。这是设计提示对照实验的切入点。

## 训练与推理的实际成本

原文研究多个规模的语言模型及大语料训练。推理示例越多，prefill 的输入越长，显存与延迟也会变化；“不用梯度更新”不意味着零成本。示例应来自允许使用的训练或开发数据，不能把测试答案混进上下文。参数规模、tokenizer、上下文长度与预训练数据一起影响结果，不能只替换一个规模数字就声称复现。

与 [BERT](bert.md) 相比，这里采用因果生成接口；与 [InstructGPT](instructgpt.md) 相比，这还不是针对人类偏好进行后训练的聊天助手。基础模型擅长续写不代表它稳定遵循指令，这正是后续工作的动机之一。

## 原文实验怎样形成证据

§3 按任务呈现结果；§3.9.1 与表 3.9 的算术任务能看到位数增加时的性能变化，不能因为两位加法成功就宣称学会任意长度算法。§3.8 的自然语言推断结果和 §5 的局限提供反例。图 1.2 把规模与上下文示例共同变化，但“更多示例更有效”不等同于确定其内部采用了某个显式学习算法。

§4 检查测试集与训练语料重叠。评估污染不是只靠删除完全相同字符串就能彻底排除的问题；因此讲义中的这些结论标为作者实验，而非无条件能力证明。本仓库没有训练或复现 GPT-3。

## 实践连接与失败条件

通过 [minigpt 实验](../../labs/minigpt/README.md) 理解下一 token 目标，再在 [Transformers](../projects/transformers.md) 中区分 `forward`、候选评分和 `generate`。推荐做小规模教学对照：固定同一模型与测试集，只变示例数量或顺序，报告准确率、输出格式合规率和输入 token 数；这属于提示实验，不是 GPT-3 规模复现。

失败可来自示例顺序敏感、上下文中混入错误标签、超出长度、世界知识过时、未校准置信度或算术不稳定。温度为零只能减少采样随机性，不能把错误变成正确。

## 把提示实验设计成可以归因的比较

提示中的示例至少有三种作用：说明任务本身、规定标签映射、展示答案格式。某个模型在增加示例后变好，可能只学会了输出约定，不一定获得新的抽象求解能力。因此可以设计分层对照：先保持题型不变只改格式，再保持格式不变改标签名称，最后才改变问题难度。这样比简单比较一条零样本和一条少样本提示更有解释力。

示例顺序也不只是书写习惯。靠近问题的示例可能对当前预测产生更强影响，同一类别连续出现可能诱发输出偏置。如果用某种顺序试了很多次，挑出测试集表现最好的顺序，就已把测试集用于选择方法。应在开发集确定提示，再在独立测试集报告结果，并尽量报告多个预先规定顺序的变化范围。

选择题概率评分需要额外小心。若标签写成单个字母，模型可能偏好某个字母的先验；若写完整答案，不同长度又影响序列概率。可以通过打乱答案位置、比较标签与完整答案协议来识别这种影响，但一旦改变评分方式，就应分别报告，不能只保留更有利的一种。

上下文长度是一种有限资源。增加示例可能挤掉题干、关键条件或更相关的例子，截断位置决定模型实际看到了什么。记录完整提示的有效长度、示例数量和被截断部分，常比只报告一个温度参数更重要。如果输出失败是因为输入条件被裁掉，就不能直接解释为推理能力不足。

最后，重复问同一问题得到一致答案只说明模型在该提示与解码设置下稳定，不证明答案正确。真实性需要外部证据或可验证答案，算法能力需要变化范围足够广的测试。把稳定性、格式遵循、事实正确和泛化能力拆成独立观察，才能避免用几段令人印象深刻的文本代替系统评估。

## 自测与答案

1. **few-shot 时参数会变吗？** 原文的任务评测不更新参数，变化的是上下文条件。
2. **模型输出流畅能证明答案真实吗？** 不能，训练目标优化文本概率，没有逐条外部事实验证。
3. **比较两种提示最先固定什么？** 模型版本、测试集、示例来源、解码配置和评分协议；否则观察无法可靠归因于提示。
